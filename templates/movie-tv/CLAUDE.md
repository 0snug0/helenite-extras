# CLAUDE.md

A Helenite vault for a film and TV diary. Notes are generated by Python sync scripts from Letterboxd (films) and Serializd (TV); the Home, Downloadrr and Downloadrr TV apps read them. There is no build. The scripts' tests: `cd 99_Internal/Templates/Scripts && python3 -m unittest discover -p 'test_*.py'`.

## Layout

| Folder | Holds |
| --- | --- |
| `00_Home/` | A note that opens the Home app. |
| `10_Inbox/` | New notes. |
| `50_Personal/Letterboxd/Films/` | One note per film: `<Title> (<Year>).md`. |
| `50_Personal/Letterboxd/People/` | One note per person credited on two or more watched or watchlisted films. |
| `50_Personal/Letterboxd/Recs/`, `Upcoming/` | Dated logs of the daily picks and the weekly New & Upcoming row (`YYYY/MM/DD.md`). Nothing reads them. |
| `50_Personal/Serializd/Shows/` | One note per TV show, same shape as a film note with `Type: Show` and `tmdb_type: tv`. |
| `99_Internal/Templates/Scripts/` | The sync scripts (`film_store.py` defines the note shape) and their tests. |
| `99_Internal/Views/` | DataviewJS views the notes embed (`film-credits`, `person-films`, `movie-*`, `tv-home`) and `films-lib.js`. |
| `99_Internal/Data/` | JSON the scripts and apps share (see "State"). |
| `99_Internal/launchd/` | launchd agent templates (filled in by `setup/SETUP.md`). |
| `Apps/` | Home, Downloadrr, Downloadrr TV. |

## Film and show notes

The frontmatter is the whole history, as flat lists and scalars:

- `watches`, `ratings`, `letterboxd_guids`: parallel lists, one entry per viewing, oldest first. `watch_count`, `last_watched` and `rating` are derived on every save.
- `on_watchlist` + `watchlist_added`, `pending` + `pending_added`: independent flags. `pending` is the download intake queue ("+ Obsidian" on Home sets it).
- `recommended`, `upcoming`: the days a film was a daily pick or in New & Upcoming.
- `directors`, `writers` + `writer_jobs`, `cast` + `cast_roles`: links to person notes with the role in the parallel list.
- `lb_rating`, `rt_score`, `rt_audience`, `rt_url`, `scores_checked`, `score_day`.

The body holds the poster, the credits block between `%% credits:start %%` and `%% credits:end %%` (regenerated), and `## Watches` with a `### YYYY-MM-DD ★★★★` heading per viewing. `## Watches` and the credits markers are load-bearing.

Rules:

- Write notes through `film_store.py` (Python) or `99_Internal/Views/films-lib.js` (views); never edit frontmatter with regexes. The two must stay identical in key names, key order, quoting and the filename rule.
- Don't delete film notes or their `letterboxd_guids`: the guids are the feed's dedup key, and a deleted note's recent watches come back on the next sync.
- `tmdb_id` + `tmdb_type` and `letterboxd_slug` are the match keys. Don't rename frontmatter keys; the views and scripts read them literally.
- Unwatched, unlisted film notes are expected: every daily pick and New & Upcoming film gets one.
- Filenames drop `/ \ : * ? " < > |` and `# ^ [ ]`; a clash gets ` (tmdb-<id>)` or ` (<n>)`.

## State

`99_Internal/Data/people-index.json` (TMDB person id → filename), `movie-recs-history.json` (the recommender's cooldown) and `history/` are state, not caches: don't delete them. `movie-recs.json`, `movie-releases.json` and `tv-home.json` are the latest lists and are rewritten by the scripts. `movie-recs-blocked.json` is the shared "never suggest" list (the ✕ on Home appends to it).

## Locking

Every Python entry point that writes notes holds one `flock` (`film_store.lock()`). Functions called under it must not take it again. The apps and views don't take it.

## Secrets

The scripts read `TMDB_TOKEN` (and optional `OMDB_API_KEY`, `RADARR_API_KEY`, `SONARR_API_KEY`) from the environment or a git-ignored `.env` at the vault root. The apps take their keys from Settings → Secrets. Never print, copy or commit a secret.
